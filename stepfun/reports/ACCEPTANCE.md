每个独立浏览器用例包含 8 项检查：启动版本、文件导入/刷新、后端路径、检索/原文、重复去重、增量导入、集合切换隔离、真实 512 维归一化向量与应用请求。最终 6 例共 48 项通过；均未观察到应用向外部 HTTP 服务发请求，测试集合全部清理成功。此网络观察只覆盖受测应用会话，不代表浏览器自身后台服务的全部流量。

版本发布分批进行。Chrome 官方 active releases 数据确认 .73 正在稳定通道推送，另列出了早期 157 小流量与 .74；本报告只主张已列明版本的实测。Edge 版本与微软 Windows x64 Stable 元数据一致。故障用例覆盖模型加载失败，不覆盖驱动崩溃或运行中设备丢失。测试准备阶段的旧版本启动与便携 Edge 崩溃记录单独归档，不计入最终通过数。

本次修复了数据库重启后的 SDK 失效连接（只自动重试读取）、导入后残留的查询耗时，以及模型缓存命中标记。缓存标记修复后重新运行全部 18 轮；各配置首轮清除模型 Cache Storage，后两轮复用。第一次实验仅作为工作区临时记录，不作为最终报告。

FP16/WebGPU 的文档编码吞吐提高，但查询端到端延迟从 FP32/WebGPU 的 22.58 ms 增至 27.31 ms。没有把所有指标描述为提升。模型质量只在 16 文档/12 查询的小型固定集上验证，不代表更大规模数据上的表现。

原始证据：browser-benchmark.json、browser-acceptance.json、database-restart.json、api-integration.json、model-sizes.json。统计表与计时范围见 BENCHMARK.md；独立浏览器方法、原始 JSON 与截图见 [补测报告](native-browser/NATIVE-BROWSER-REPORT.md)。
